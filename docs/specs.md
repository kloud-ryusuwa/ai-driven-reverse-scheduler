# AI-Driven Reverse Scheduler

計画を余裕を持って、かつ動的に管理・改組するアプリケーション。

## Concept

よくあるのが、完璧に逆算した計画を立てても、見積もりの甘さや突発的なタスクによって、必ずスケジュールは狂う。
既存のツールは「遅れたタスクを空き時間に詰め直す」という機能を搭載しているだけに過ぎない。
ここで、本システムは「間に合わないなら、スコープ自体を削る」という決断を、AIが自律的に提案・サポートする。

## Goal

単なる「予定の再配置」ではなく、コアとなる要素を中心に必ずプロジェクトを着地させることを目的とする。

## Core Engine

システムは、スケジュールの限界を検知し、タスクの要件を意味論的に縮小する。

*   **Buffer Management**
    タスクの総工数から最初から20%をバッファとして差し引き、「実質締切」をシステム内部で保持する。
*   **Dynamic Urgency**
    残工数と残日数の比率から「今日サボった場合の明日の負荷」を計算し、タスク状態をGreen/Yellow/Redで視覚化する。
*   **Just-in-Time Prompting**
    初期は「タスク名」と「締切」のみ。進捗がYellow（警告）になったタイミングで初めて、AIがスケジュールの立て直しに必要な情報（重要度・目的）をユーザーに要求する。
*   **AI Scope Triage**
    スケジュールがRed（危険）に突入した際、LLMが「なぜこの作業を削っても（手を抜いても）目的は達成できるのか」という論理的理由と共に、タスクの完全削除や簡略化を提案する。

## Status

🚧 Early-stage / MVP Development
現在はプロトタイプ実装フェーズ。依存関係の描画や外部カレンダー連携を削ぎ落とし、AIによる「トリアージ提案（理由付け）」のコアロジック検証に集中している。

### 将来追加予定の機能案

- **サブタスクの順序強制（依存関係の明示）**
  - ユーザーまたは AI が各サブタスクに対して「このタスクの前に完了している必要があるタスク」を指定できる
  - 依存関係を考慮したスケジュール計算（クリティカルパスの検出、並列実行可能タスクの特定）
  - トリアージ提案時に依存制約を尊重し、依存元を削減・簡略化する場合の影響範囲を明確に提示
  - UI 上でブロック中タスクと実行可能タスクを視覚的に区別
- **中間達成目標（マイルストーン）**
  - プロジェクト期日までの間に「この日までに〇〇まで完成させる」といった中間チェックポイントを設定
  - マイルストーンごとに担当サブタスク群を紐づけ、個別の進捗率とバッファ状況を可視化
  - マイルストーンの期限超過リスクを早期検知し、プロジェクト全体のトリアージ判断に活用
  - 例：「ここまでにフロントの上っ面だけでも完成させておく」といった段階的なゴール設定
